- Current query packing is row-SIMD: one slot per query and one vector per feature. - Main binary evaluation performs one comparison per tree depth, refreshes the branch bit after every depth, and splits path state into even/odd parity tables of sizes `2^ceil(d/2)` and `2^floor(d/2)`. Forest bootstrapping batches up to eight branch bits with default `Logbase=4` across real and imaginary channels.
- Complexity reconciliation from the primary paper: `O(p·2^{D/2})` is derived for **key-switching operations**, treating key switching as the dominant cost of ciphertext multiplication. BSGS forms `p·2^{d/2}+2p` lazy ciphertext inner products at depth `d`, each relinearized once, plus `2^{d/2}` GenOH key switches. The local `select1D` matches this mechanism: it accumulates all `MulNew` degree-2 products and invokes `Relin` once per inner product. However, it still executes `Theta(p·2^d)` raw ciphertext tensor products across the first-stage inner products. Both the paper's dominant-key-switch model and the full tensor-product count must be reported; “server complexity” is otherwise ambiguous.
- Exact source count for one encrypted attribute channel at depth `d`: with `M=2^ceil(d/2)` and `S=2^floor(d/2)`, `selectByParity` performs `S` inner products of length `M` and one of length `S`, hence `S*M+S = 2^d+2^floor(d/2)` tensor multiplications but only `S+1` relinearizations. Across `p/2` complex-packed channels, tensor products/additions remain `Theta(p*2^d)` while relinearizations are `Theta(p*2^(d/2))`.
- The repository is a monolithic benchmark harness, not a two-party protocol implementation: key generation, encryption, evaluation, decryption, and validation run in one process. A conceptual client/server split is possible, but setup/evaluation-key traffic and transport are not implemented or measured.

- Multiway/integer trees require a new radix-aware tree/state model. Current node counts, BFS layout, parity state, `BalancedProducts`, and leaf indexing all hard-code binary branching.

## Technical Decisions

| Decision | Rationale |
|---|---|
| Preserve separate `reference`, `port`, and `optimized` result classes | Prevents a performance-oriented rewrite from being mislabeled as reproduction. |
| Define exact modular semantics before porting operators | CKKS approximate arithmetic can only support `Z_{2^n}` claims under explicit representation, rounding, range, and error invariants. |
| Benchmark operator counts and wall-clock behavior | Asymptotic savings may be erased by rotations, bootstraps, key switching, packing overhead, or parameter changes. |
| Use independent plaintext oracles and upstream vectors | Avoids tautological tests that repeat the encrypted implementation's logic. |
| Treat the current successful `go test` as a compile smoke test only | There are no test files, so it provides no behavioral or cryptographic correctness evidence. |
| Prefer WSL2 for any C/C++ upstream reference build, while keeping the Lattigo port native Go-compatible | The required GNU/CMake toolchain exists in WSL but not on native Windows; separating environments avoids conflating port behavior with reference-build friction. |
| Preserve current binary-tree evaluator unchanged as a CKKS baseline | It enables a strict comparator-only substitution before any tree-topology optimization changes semantics. |
| Separate operator correctness parameters from secure benchmark parameters | The upstream ALU demos may use small/non-secure parameters; only explicitly 128-bit configurations can support performance/security claims. |

## Visual/Browser Findings

- The official ACM SIGSAC CCS 2026 accepted-paper page lists `Low-Complexity Private Decision Tree Evaluation over Homomorphic Encryption` by Dongjin Park, Gyeongwon Cha, and Joon-Woo Lee. This verifies acceptance and authorship but does not expose the manuscript PDF or DOI yet.
- The publicly indexed author abstract states that the protocol is non-interactive and CKKS-based, uses OBO comparisons, BSGS branch selection and level-major batched bootstrapping, and claims end-to-end `O(p sqrt(2^D))`; the full manuscript and checkout confirm the construction but narrow this asymptotic claim to key switching/relinearization rather than all ring operations.
- IACR ePrint 2026/233 resolves to `FHE for SIMD Arithmetic Logic Units with Amortized O(1) Bootstrapping per Ciphertext`; the IACR record is the primary paper source.
- The official `tsinghua-ideal/fhe-simd-alu` repository documents arithmetic, bitwise logic, shifts/rotations, comparison and bootstrap demos; it explicitly labels ring dimension 1024 as demonstration-only and points to `benchmark-full` for an RLWE parameter set intended to satisfy 128-bit security.
- The primary manuscript for LCPDTE is IACR ePrint 2026/1263 (received 2026-06-16, approved 2026-06-19, CC BY) and is marked as published elsewhere at ACM CCS 2026. This replaces the earlier “paper unavailable” uncertainty.
- The primary Gao–Zheng record for ePrint 2026/233 was revised on 2026-06-08 and is identified as a major revision of a CRYPTO 2026 publication. Its abstract names triangle encoding, conversion to discrete-CKKS Boolean mode, two-bootstrapping refresh, and an RLWE-induced SIMD structure as the core mechanisms.
- The Gao–Zheng abstract's amortized `O(1)` claim is per ciphertext only when `O(n)` iterations are amortized across `O(n)` ciphertexts/machine words; it is not a claim that one isolated word has constant total bootstrap work. This batching precondition must be preserved in the Lattigo cost model.
- Visual inspection of LCPDTE PDF pages 5–10 confirmed Algorithms 1–5, their symbols, and Tables 4–5 against extracted text. In particular, Algorithm 2 bootstraps every level decision, Algorithm 4 separates even/odd one-hot factors, and Algorithm 5 reduces `K·D` logical bootstraps to `D` batch-bit bootstraps for `K` trees.
- LCPDTE Table 4 uses `log N=16`, `log QP=1328–1508`, dense/sparse secret weights `(192,32)`, base scale 45, and a depth-dependent circuit chain; the paper states 128-bit security but does not show an estimator transcript in the main text. This parameter tuple needs independent estimator verification before a secure-performance claim.
- The local single-tree parameter chain matches most Table 4 level sizes, but the main secret is configured with Hamming weight `32768`, not the paper's `192`. The `Logbase=4` batch path at depth 12 has effective `log QP` about 1643 and uses real/imaginary halves to fit eight bits into five LUT levels; neither difference is clearly represented by Table 4. Security and performance claims therefore require a local effective-parameter manifest rather than citing the table.
- The paper pseudocode contains several non-cosmetic transcription problems: the printed GEQ product index does not encode the intended lexicographic recurrence; Algorithm 1 mixes `Tail`/`flag` and its return annotation; Algorithm 4 has inclusive-loop/off-by-one and output-type inconsistencies. The checkout follows the mathematically intended ordering, so the source code plus induction—not the literal pseudocode—is the reproduction oracle.
- The appendix pairs bit `j` with bit `p/2+j` in complex channels, whereas the checkout pairs adjacent MSB-first bits and divides both by two before reconstructing them with conjugation. The local transform is functionally valid but is an implementation variant, not a byte-for-byte implementation of the appendix encoding.
- The ordered-float transform distinguishes `-0` from `+0` and imposes an arbitrary NaN order. The shipped dataset has neither NaNs nor negative zero and its models have no active default-left/categorical split, but a general decision-tree API must define these cases explicitly.
- LCPDTE's experimental comparisons use all baselines in Lattigo, but the BFV baselines are run at `log N=15` with the smallest modulus that preserves correctness while matching batch size; they are not the target protocol itself. The paper reports the CKKS target as slower at shallow depths, crossing all baselines at `D=7` and reaching 42.2055 ms amortized at `D=12` for 32,768 slots.
- Visual inspection of Gao–Zheng PDF pages 15, 21–23, 26–27, 41 and 47–48 confirmed Definitions 9–15, the A2B/B-A2B flow, security/parameter tables, Boolean operations, and both algorithm listings against extracted text.
- Gao arithmetic mode represents `m ∈ Z_{2^n}` in `Z_R = R[X]/<X^n-X+2>` as `ΔI + (Δ/(X-2))[m]_t + e`. Exact decode first coefficient-wise rounds `(X-2)f/Δ` and then evaluates at `X=2`; Theorem 1 requires `||(X-2)e||∞ < Δ/2`. Addition preserves the form; full multiplication consumes two CKKS levels, while `MultShort` consumes one.
- Full packing induces `N/n` arithmetic machine-word slots per RLWE ciphertext and `N/(2n)` Boolean word slots. At `N=2^16`, this is only 2,048 arithmetic or 1,024 Boolean 32-bit words per ciphertext, versus LCPDTE's 32,768 query slots. Matched-throughput comparisons must therefore charge the extra ciphertext blocks; per-ciphertext timing alone is misleading for PDTE.
- A2B uses chunk width `w=log2 p=4`, so a word of width `n` needs `d=n/4` iterative D-CKKS LUT passes. Batched A2B processes `n/4` arithmetic ciphertexts together using `n/4` bootstraps, amortized to one bootstrap per input ciphertext—not one bootstrap for the entire batch.
- Gao Boolean comparison is not a standalone optimized comparator: Appendix B defines comparison as arithmetic subtraction followed by A2B and Boolean sign extraction. A PDTE port therefore needs either full A2B or a new, separately validated sign-only specialization.
- The upstream `EvalLessThan` has no modular-overflow correction: it computes `d=x-y`, converts `d` with A2B, and returns the sign bit. This fails for general signed comparison when subtraction overflows (for example int8 `127-(-1)` wraps to `-128`) and is not an unsigned comparator. The Lattigo API must expose signedness/range contracts and implement either one-bit widening/borrow or the standard sign-overflow correction.
- **Innovation hypothesis:** PDTE only needs the sign/branch bit, not all `n` Boolean bits. A source-derived but not paper-claimed `A2Sign` specialization may be able to retain only `LUT_MSB` for the high corner and avoid full A2B recombination. This must be proved against the triangle layout and implemented as an exploratory operator; it cannot be labeled a faithful Gao primitive yet.
- Gao Table 5 uses `N=2^16`, `log Δ=43`, CKKS depth 20, `log QP=1254`, secret weights `(192,32)`, Gaussian error `σ=3.2`, and claims 128-bit security via BTH22. The paper additionally requires application-aware noise/software control; an RLWE estimator result alone is insufficient for its correctness/security claim.
- Gao's paper reports OpenFHE v1.4.2, while the pinned authoritative repository declares `OPENFHE_VERSION=1.4.0`. This version discrepancy must remain in the reproduction manifest and prevents describing the checkout as an exact dependency match without an author-provided tag.
- The upstream roots for `n in {8,16,32,64,128,256}` are committed as 128-bit fixed-point constants rather than solved at runtime with doubles. A faithful Lattigo port should preserve those constants and use Lattigo `bignum`/`lintrans` types plus the paper's closed-form Vandermonde inverse; a `complex128` root solver is suitable only as an independent diagnostic oracle.
- The decision-tree minimum Gao subset is triangle encode/decode, Add/Sub, A2B or A2Sign, Boolean sign/NOT/AND as required by path state, rotations/masks, B2A, and MultShort for `L+b(R-L)`. Full multiplication and A2A are conditional on an evaluated tree design's arithmetic depth/noise; implementing the entire general-purpose ALU before the comparator seam would add work without evidence of tree value.
- Sign-only A2B cannot simply jump to the high chunk: low-chunk `LUT_ID` peeling carries information into later chunks. It may discard low-chunk `LUT_MSB` outputs and their accumulation/masks, reducing memory/rotations, but bootstrap count remains an empirical question.
- A radix-`r` threshold node normally costs `r-1` comparisons while depth becomes `log_r L`; `(r-1)log_r L` is not automatically below binary. A plausible gain requires SIMD-parallel thresholds, cheap digit formation, or direct small-domain LUT classification, and encrypted child indices still cannot drive data-dependent CKKS rotations without a separate selection construction.

## 2026-09-01 Route-B secure-profile root-tree finding

- Complete Route-B A2B exposes the high Boolean half as `[b4,b5,b6,b7]` at L5/S43. For a signed-int8 comparison, only `b7` is needed. A rank-one four-diagonal linear transform can copy column 3 into all four positions using rotations `[1,2]`; its Q4 multiplication and one rescale return a repeated arithmetic selector at L3/S43. This is a shorter root/public-leaf bridge than the earlier periodic-selector decoder.
- The bridge is numerically validated over all signed-byte values for threshold zero and public real leaves: 512 encrypted words, 2,048 decoded slots, zero branch/output mismatches, maximum absolute error `4.1591e-7`. The frozen JSON SHA-256 is `2410DC16...5FB67C`.
- The optimization is depth-local. The selector exits at L3, too low to multiply L20 feature/threshold ciphertexts and still feed another full A2B. Secure depth-2 composition therefore needs an explicit refresh/reraising design, a lower-ingress child conversion, or a fused selection/conversion circuit. The root result does not justify removing periodic decoding or refresh from deeper trees.
- The admitted domain is signed int8 with a trusted no-overflow endpoint certificate, public threshold and public real leaves. It is an R1 quantized decision-tree slice, not source-faithful CCS float32 semantics, not private-model evaluation, and not a radix-tree result.

## 2026-09-01 Route-B depth-2 node-batch finding

- The L3 selector egress does not need an immediate refresh when every internal node is compared in the same A2B batch. Packing `(root,left,right)` in adjacent words lets one complete conversion produce all three signs. Q3 role masks plus `+4/+8` rotations align them, and three CT--CT path products select one of four real leaves at L0.
- Sparse CKKS slot masks are not meaningful at scale one in this profile. Their inverse-FFT coefficients are fractional and rounded during encoding. Encoding at the consumed modulus scale and physically rescaling is part of the circuit semantics, not an implementation detail.
- The accepted 170-query run has zero active or inactive mismatches across all 2,048 slots. Depth-2 wall is `28.8937126 s`, including `26.8006752 s` for complete A2B. The frozen JSON SHA-256 is `8B99E96E...D85D8`.

- A multiway integer node remains a viable hypothesis only if digit/equality and multiway-mux cost is outweighed by reduced tree depth at matched model quality. C73 implements binary all-node evaluation; it does not yet implement or validate a radix tree.
