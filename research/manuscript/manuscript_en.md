## Draftable manuscript text

### 1. Introduction

Private decision-tree evaluation (PDTE) computes a tree or forest prediction from encrypted client features while keeping the server's model in the protocol's declared privacy scope. The task couples numerical representation to discrete control flow: a small error is harmless only while it does not change a branch decision, and every branch representation affects the cost of comparison, path-state update and leaf selection. LCPDTE addresses this setting with a CKKS-based non-interactive protocol that combines one-by-one selection (OBO), one-hot generation and BSGS traversal across packed queries (Park et al., 2026) <!--ref:park2026lcpdte--><!--anchor:page:5-10-->.

The central systems bottleneck is multidimensional. OBO reduces the number of active comparisons to the tree depth, while BSGS reduces selected key-switch and relinearization costs. The underlying implementation still performs exponentially many raw tensor products and additions for a complete depth-$D$ tree, so the square-root term does not describe total ring work (Park et al., 2026) <!--ref:park2026lcpdte--><!--anchor:page:9-15-->. A fair evaluator must therefore report comparison provenance, ciphertext multiplications, relinearizations, rotations, bootstraps, live states, communication, latency and memory on the same workload.

Discrete computation over CKKS adds a second constraint: correctness belongs to an encoding-and-cleaning contract, not to an approximate value alone. Error-cleaning and specialized bootstrapping methods maintain bits, small integers or lookup-table outputs only while the ciphertext stays inside the corresponding decoding region (Drucker et al., 2024) <!--ref:drucker2024bleach--><!--anchor:page:1-3-->; (Bae et al., 2024) <!--ref:bae2024bits--><!--anchor:page:1-3-->; (Alexandru et al., 2025) <!--ref:alexandru2025functional--><!--anchor:page:6-25-->. This contract makes decoding margin, bootstrap failure and representation mode first-class evaluation quantities.

Gao and Zheng provide a word-level route through the triangle-ring representation. An $n$-bit residue is represented in $R_n=\mathbb{R}[X]/(X^n-X+2)$ with $\tau=X-2$; decoding applies $\tau$, rounds coefficients and then evaluates at $X=2$ modulo $2^n$ (Gao and Zheng, 2026) <!--ref:gao2026alu--><!--anchor:page:15-17-->. Their A2B and B-A2B procedures connect arithmetic words to Boolean computation, but their amortization depends on batch occupancy (Gao and Zheng, 2026) <!--ref:gao2026alu--><!--anchor:page:21-23-->. At the matched 32-bit, 32,768-query workload, both the LCPDTE adjacent-bit layout and the Gao arithmetic layout require 16 physical input ciphertexts per feature (Park et al., 2026) <!--ref:park2026lcpdte--><!--anchor:page:7-15-->; (Gao and Zheng, 2026) <!--ref:gao2026alu--><!--anchor:page:14-16-->. The potential gain lies in the downstream operator graph.

This paper studies that operator graph as one system. It connects a high-precision Pure-Go triangle-ring layer to explicit branch contracts and to binary/radix-aware PDTE evaluators, then tests the resulting designs under matched model semantics, batch occupancy, security eligibility and host resources. The evaluation is outcome-neutral: a design enters the reported Pareto frontier only after it passes correctness and security gates, and a lower tree depth counts as a systems gain only when selector width, conversion work and communication are included.

### 2. Background and Related Work

#### 2.1 PDTE decomposes into comparison, state update and leaf selection

PDTE protocols optimize different parts of the encrypted control-flow pipeline. One-branch designs reduce the number of evaluated comparisons, batched designs amortize comparator cost across queries, and traversal designs restructure path or leaf selection. These mechanisms cannot be ranked from a single complexity term because they move work among ciphertext multiplication, key switching, rotations, bootstrapping, state cardinality and communication. The present study uses the decomposition

$$
C=C_{\mathrm{compare}}+C_{\mathrm{active\ select}}+C_{\mathrm{path\ update}}+C_{\mathrm{leaf\ select}}+C_{\mathrm{refresh}}+C_{\mathrm{online\ I/O}}
$$

as the common accounting frame.

#### 2.2 Triangle-ring words require ordered decoding

The triangle-ring representation stores the algebraic object needed for modular word operations rather than an ordinary scalar integer. Its arithmetic representation is $\tau^{-1}[m]_\tau$, and its short representation is $[m]_\tau$. Addition and subtraction act on arithmetic representations, `MultShort` combines an arithmetic left operand with a short right operand, and `MultFull` restores the arithmetic form with the required $\tau$ factor. The decode order is part of correctness: apply $\tau$, round every coefficient, and evaluate the resulting polynomial at $X=2$ modulo $2^n$.

#### 2.3 SIMD gain depends on occupancy

Functional and discrete CKKS bootstrapping can process many equal-domain operations in parallel, but the reported throughput depends on how fully the RLWE/SIMD capacity is occupied. Bit bootstrapping, small-integer bootstrapping and multi-value functional bootstrapping all expose this occupancy dependence (Bae et al., 2024) <!--ref:bae2024bits--><!--anchor:page:1-3-->; (Bae et al., 2024) <!--ref:bae2024small--><!--anchor:page:1-7-->; (Alexandru et al., 2025) <!--ref:alexandru2025functional--><!--anchor:page:6-10-->. The evaluation therefore reports physical ciphertext count, logical queries, useful word capacity, padding and batch utilization together.

#### 2.4 Radix changes both depth and selector width

A radix-$r$ interval node reduces logical depth to $\log_r L$ for $L$ leaves but ordinarily requires $r-1$ thresholds and an oblivious $r$-way selection mechanism. For a complete uniform tree, the active-route comparison count is $C_r(L)=(r-1)\log_r L=\ln(L)(r-1)/\ln r$. Because $(r-1)/\ln r$ increases for $r>1$, binary minimizes independent threshold comparisons at fixed $L$. An encrypted child digit also cannot directly choose a Galois rotation. Radix-aware PDTE is therefore a trade-off among dependency rounds, comparison amortization, lookup-table scheduling, selector width and live ciphertext state—not a depth-only optimization. R0 compilation preserves every original binary predicate and leaf; R1 design changes the model and reports its accuracy and model-conversion effects separately.

#### 2.5 Security attaches to the full application and parameter chain

CKKS bootstrapping security and correctness depend on the complete modulus chain, secret distributions, key-switch parameters, error model, application circuit and decoding rule. Sparse-secret encapsulation makes the dense main secret and low-modulus sparse bootstrapping secret separate parts of that record (Bossuat et al., 2022) <!--ref:bossuat2022sparse--><!--anchor:page:1-4-->. Application-aware analysis likewise binds the security/correctness statement to the declared circuit, input set and bootstrap placement (Alexandru et al., 2026) <!--ref:alexandru2026application--><!--anchor:page:1-8-->. Ring degree alone does not make a performance row eligible for a classical 128-bit label.

#### 2.6 Direct antecedents define the candidate-composition boundary

A focused 96-query counterexample search recovered direct antecedents for every broad component claim: HEaaN-ID3 for multiway CKKS trees, PEGASUS for hybrid CKKS/FHEW private-tree evaluation, CKKS tree-based lookup tables and PROBONITE-like constructions for encrypted-index selection, and radix/discrete-CKKS work by Cha and Kim for large-integer comparison. HEGIDE is closer at the systems boundary: it evaluates private programs and private data in a discrete-CKKS oblivious processor and includes an end-to-end private depth-4 binary decision-tree benchmark, although it evaluates all instructions and paths and uses Kim-style radix digits rather than Gao triangle/A2B or LCPDTE OBO (Dumezy et al., 2026) <!--ref:dumezy2026hegide--><!--anchor:sections:4,6.1-6.3-->.

Character Block Encodings is a direct operator baseline implemented in Lattigo. It provides single-level affine lookup tables, native modular operations and a finite-state radix comparator with depth $3+\lceil\log_2 d\rceil$ for $d$ characters. Its representation allocates multiple CKKS slots per alphabet value and is structurally different from a Gao triangle word; the paper states that code will be released, but the bounded search found no authoritative release on the search date (Dumezy and Suvanto, 2026) <!--ref:dumezy2026characterblock--><!--anchor:sections:3,5-7-->.

The manuscript therefore uses a frozen-corpus candidate-composition statement, not a first, closest or absence claim. Within the recorded corpus as of 29 August 2026, no inspected primary work places the Gao–Zheng triangle/A2B representation inside LCPDTE's non-interactive OBO/BSGS model-private evaluator. The experimental question is whether that exact composition, a proved range-safe comparator and its Lattigo realization improve a matched-semantics Pareto frontier against Gao, Character Block and established PDTE/PFE baselines. ### 3. Problem and Evaluation Contract

#### 3.1 Parties, inputs and outputs

The protocol has two semi-honest, non-colluding parties. The client holds the feature vector and secret key. The server holds the plaintext binary tree or forest, including thresholds and leaf values, and evaluates the prescribed circuit. The client receives the prediction. Tree depth, forest size, feature count, batch size, ciphertext shape and cryptographic parameter dimensions are public metadata. Online request/response traffic is reported separately from setup and evaluation-key traffic.

#### 3.2 Semantic classes

The binary PDTE baseline evaluates the frozen source model. An R0 variant may replace operators or group consecutive binary levels, but it must preserve every split predicate, equality convention and leaf mapping. Prediction equality is mandatory. An R1 variant may retrain, prune, quantize or introduce genuine multiway nodes; its model size, predictive accuracy and leakage surface are measured before its HE cost is compared.

#### 3.3 Correctness and security eligibility

Arithmetic wraps modulo $2^n$ for unsigned and two's-complement interpretations. Each representation declares its canonical residue interval, encoding, decoding rule and unique-decoding radius. A result is correct only when the decoded residue or branch selector matches the independent plaintext oracle and the measured representation error remains within the preregistered margin. Secure-performance eligibility additionally requires the complete CKKS/RLWE parameter tuple and an archived estimator transcript for the declared classical 128-bit target.

#### 3.4 Decision rule

Correctness and security are hard gates. Eligible designs are compared on median online latency, peak RSS, bootstrap count and online communication; the paper reports the nondominated Pareto set. For a single deployment recommendation, the preregistered rule first minimizes median online latency, then peak memory, then online communication. Skipped, timed-out and resource-infeasible configurations remain visible in the result artifact.

### 4. Integer-Aware LCPDTE Design

#### 4.1 System overview

The system separates mathematical semantics from encrypted execution and tree scheduling. The `integer/z2n` package defines the triangle-ring oracle. `integer/homchain` compiles the root/coefficient transforms into CKKS linear transformations. `integer/evaluator` binds arithmetic and short words to ciphertext metadata and operators. `integer/treeplan`, `integer/treecompile` and `integer/treeeval` preserve the distinction among binary, R0 and R1 model semantics. This separation allows every encrypted operator to be checked against an independent modular oracle before it enters a tree circuit.

#### 4.2 High-precision triangle-ring oracle

For $n\in\{8,16,32,64\}$, the oracle constructs $R_n=\mathbb{R}[X]/(X^n-X+2)$ and $\tau=X-2$ at 256-bit working precision. Published root constants retain their signed 128-bit fixed-point provenance. The oracle implements binary and arithmetic encoding, ring reduction, modular Add/Sub/Multiply, coefficient-wise rounding and recovery at $X=2$. Every object carries word width, precision, polynomial modulus, $\tau$ convention and root-source provenance. The public polynomial constructor imports each coefficient into the ring precision and rejects values for which subtracting the canonical $2^{-n-1}$ epsilon is no longer observable. Tests across all four word widths retain admissible mixed-precision inputs and reject the constructed $2^{300}$ loss-of-significance case.

*Evidence state: supported as a Pure-Go mathematical oracle (C02). Experimental counts remain in E1.*

#### 4.3 Full-slot homomorphic transform

The homomorphic chain maps packed root slots to two coefficient halves and recombines them after coefficient-domain work. Each $n$-bit word occupies one independent block, and the compiler repeats the same U/V block across the full slot vector. Boundary entries are masked so a diagonal rotation cannot read from an adjacent word. The transform family includes normal, special-$b_0$, fused-$\tau$ and fused-$\tau^{-1}$ variants. Galois-element enumeration now validates the complete transform state and returns an error for an invalid specification, preventing construction failure from collapsing into an empty key set.

*Evidence state: supported for the four-word functional-test configuration (C03). Secure and large-occupancy claims remain in E2 and E8.*

The current Stage-2 path composes Z-To-C, raw SlotsToCoeffs, guarded ScaleDown, ModUp/Trace, raw CoeffsToSlots and C-To-Z for a dense, full-packed $n=8$ slice. #### 4.4 Encrypted arithmetic and representation metadata

The early codec metadata carries a ciphertext, word count, slot use, level, scale, word width, arithmetic/short mode, signedness, declared bounds and a caller-supplied security boundary. Arithmetic and short modes are distinct types: linear arithmetic accepts arithmetic operands, while `MultShort` requires a short right operand. The functional implementation provides encode/decode, Add, Sub, Negate, public linear variants, `MultShort` and `MultFull`. Each operation returns a fresh ciphertext and updates level/scale metadata from the executed rescale chain.

This codec record is not the frozen Stage-2 public integer profile. It does not yet distinguish Boolean low/high halves, coefficient versus root-slot state, upstream-faithful versus Lattigo-adaptation provenance, packing mode/`LogSlots`, or typed unknown physical observations. Its `ExternallyValidated` value is a declaration, not an estimator result. Heterogeneous A2A/A2B/B2A/tree composition therefore requires a separate fail-closed metadata/profile seam.

The Stage-2 P0 metadata draft specifies that seam as an immutable certificate with orthogonal closed axes for integer semantics, algebraic domain, half role, signedness, packing, fidelity and maturity. It binds exact scale snapshots and range evidence to a profile digest, separates logical counts from optional physical observations, and permits fidelity or security promotion only through controlled verifiers. Eight negative tests target representation rebinding, half swapping, transform-family confusion, raw-representative collapse, scale tampering, caller-driven promotion, unknown-as-zero serialization and mismatched measurement attachment. *Evidence state: supported as a design contract (C27), not yet as an implemented or audited public API.*

#### 4.5 Conversion and branch extraction

The branch layer separates a faithful conversion path from an exploratory specialization. A2B and B-A2B reconstruct the Boolean representation required by the Gao–Zheng operator contract. A2Sign asks a narrower question: whether the branch/sign output can be retained without materializing the full Boolean word. Both routes feed a range-safe comparison interface whose signedness and overflow conditions are explicit. A selector then maps a branch bit $b$ to

$$
\operatorname{Select}(b,L,R)=L+\operatorname{B2A}(b)\cdot_{\mathrm{short}}(R-L).
$$

The first concrete signed comparator slice fixes $n=8$ two's-complement inputs. An arbitrary-precision host calculation derives $d_{\min}=x_{\min}-t_{\max}$ and $d_{\max}=x_{\max}-t_{\min}$, then admits the circuit only when all four source endpoints and $[d_{\min},d_{\max}]$ lie in $[-128,127]$. Under that certificate, $d=x-t$ has no signed overflow, its high-half bit $b_7$ satisfies $b_7=1\Leftrightarrow d<0$, and the branch predicate is $[x\ge t]=1-b_7$. The one uses the block-encoded arithmetic-root-slot representation. Full-range signed subtraction, unsigned borrow and widened unsigned comparison remain separate physical circuits. The exact float32 R0 route uses an ordered-uint32 view. Phase A implements the opaque self-authenticating certificate with `big.Int` endpoint derivation and a digest over every semantic field. Exhausting all $256^2$ singleton pairs admits 49,152 and rejects 16,384 exactly according to mathematical signed-byte representability; invalid boxes and certificate mutations fail closed in five repetitions. The stable Phase-A audit returned 0 Critical, 0 Major and 0 Minor. The certificate trusts protocol-level range admission. [Signed-int8 comparator contract.](../phase3_design/signed8_comparator_contract.md)

The repaired Phase-B slice retains the fixed CT--PT/CT--CT difference, accepted serial A2B, internal `HighMSB()` binding, direct rank-one sign transform and arithmetic $1-b_7$ egress. Admission matches an explicit declared-source parameter digest to the canonical profile, returns owned ciphertext copies, seals their serialized payload digests into opaque provenance and reauthenticates the payloads after graph/key preflight immediately before subtraction. This is a trusted admission boundary, not a cryptographic proof of raw-ciphertext origin. Entry-path timing covers public-threshold encoding; setup accounting separates the cached arithmetic-one encoding from per-evaluation threshold encoding. The private-tree integration design makes the next representation boundary explicit. A comparator returns an arithmetic-root selector at $L4,S35$, whereas path products and real-leaf selection require an ordinary scalar selector repeated over each four-slot word block. #### 4.6 Binary and radix-aware tree semantics

The binary reference stores splits in breadth-first order and leaves in MSB-first path order. R0 compilation groups $g\in\{1,2,3,4\}$ consecutive binary levels into radix $r=2^g$ supernodes without changing a predicate or leaf mapping. A narrower R0 fusion is available only when every reachable split in a local subtree uses the same feature: sorting its cut points and exhaustively certifying the source leaf/state over every induced integer interval can yield an equivalent interval node or lookup table. Mixed-feature subtrees do not satisfy this one-dimensional contract. R1 nodes instead define genuine interval or model-changing multiway decisions. The type-level semantics label prevents an R1 accuracy change from being reported as an R0 operator gain.

A reproducible necessary-condition scan demotes same-feature R0 fusion from a primary mechanism to a sparse special case for the supplied workloads. The frozen D=8/10/12 raw models contain 5/13/26 same-feature internal edges among 345/453/539 internal edges (1.45%/2.87%/4.82%). Every connected opportunity contains exactly two internal nodes, the longest same-feature path run is two, and no model contains a complete uniform same-feature subtree of height two, three or four. This structural result shifts the main integer-node experiment toward R1 conversion batching, unary-to-digit fusion and reduced refresh dependencies; it does not show that any such arm is faster (C32).

Server-public constants enter the generic evaluator as exact real, unsigned or two's-complement signed scalars with an explicit bit width. Every comparator call also requires a policy that binds the scalar kind and width to the admitted operand ranges, comparator construction and overflow contract. This prevents a 64-bit integer threshold from passing through `float64`, prevents an unsigned tree from using a signed comparator, and rejects a no-overflow subtraction claim unless the declared ranges prove it.

Finite float32 trees also expose an R0 ordered-comparator view. The compiler maps negative values by bitwise complement and nonnegative values by sign-bit flip, canonicalizes both signed zeros to one key, rejects NaNs and infinities, and deep-copies the source forest. Boundary/subnormal cases and 100,000 fixed-seed random finite pairs preserve `<`, `>=` and equality; fixture routes and leaf bits remain unchanged. This view changes operand representation, not the trained model.

R0 equivalence is a verified compiler property rather than a mutable label. `CompileR0` binds SHA-256 digests of the binary source and compiled radix plan in private state. Its canonical encoder hashes semantic numeric types, widths and bit patterns directly; it neither trusts JSON output nor collapses IEEE negative zero into positive zero. Validation detects a modified plan, while `VerifyAgainst` checks the source binding and compares the plan with a fresh compilation. Hand-built, round-tripped, custom-marshaled, mutated and wrong-source plans remain structurally inspectable but cannot report R0 equivalence.

*Evidence state: supported for the generic/plaintext contract, exact-integer policy tests, certified R0 compilation, the ordered-float32 view, the corrected source-faithful/conservative/full-level cost fork and the independently accepted typed schedule-planner contract (C07–C08, C23, C25). #### 4.8 R0 execution schedules preserve operand provenance

Structural grouping does not identify a unique homomorphic schedule. For a group starting at binary depth $d$, let $S=2^d$ be the number of possible active supernodes, let $h=\min(g,D-d)$ and let $K=2^h-1$ be the number of predicates inside one supernode. The encrypted path state hides which of the $S$ supernodes is active.

#### 4.9 Radix gains require measured amortization

For $r=2^g$ and $L=2^D$, the independent-predicate construction uses $(2^g-1)D/g>D$ comparisons while reducing dependency rounds to $\lceil D/g\rceil$. A necessary latency break-even condition is

$$
\frac{T_{\mathrm{batch}}(2^g-1)+T_{\mathrm{digit}}(2^g)+T_{\mathrm{refresh}}}{g}
<T_{\mathrm{cmp}}(1)+T_{\mathrm{select}}(2)+T_{\mathrm{refresh}}.
$$

The matched multiway audit narrows this design space.
