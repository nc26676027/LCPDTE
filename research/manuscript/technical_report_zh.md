## 1. 执行摘要

**【复现事实】** LCPDTE 的核心优势是把完整二叉树每层的比较收缩为一次 OBO（one-branch-only）比较，并用 GenOH、奇偶路径分解的 BSGS 盲选择以及 level-major 批自举减少重线性化/密钥切换、峰值密文物化和自举调用。论文和代码共同支持 `D` 次比较、`O(p·2^{D/2})` 重线性化/密钥切换与 `O(2^{D/2})` 大密文缓冲；源码审计同时显示，原始 ciphertext tensor products/additions 仍为 `Θ(p·2^D)`。

**【复现事实】** Gao–Zheng 的核心不是把普通整数填入 CKKS slot，而是三个联动机制：在 `R[X]/(X^n-X+2)` 中用 triangle representation 表示 `Z_{2^n}` 机器字，用块对角同态映射连接机器字环与 CKKS RLWE 环，再用 D-CKKS LUT 完成 Arithmetic/Boolean 模式转换。A2B 对 `n` 位字需要 `n/w` 轮 chunk peeling；B-A2B 只在批次填满 `n/w` 个输入密文时，才可将该宽度成本摊销为每输入密文一次自举。

**【推导分析】** 两篇工作的直接串联不会自动产生端到端加速。Gao triangle 表示可改变比较器的密文组织和算子图，但不会自动消除 LCPDTE `select1D` 在每层对 `2^d` 节点展开的 tensor-product/addition 工作。真正的系统创新必须同时改变比较输出、批调度或路径选择数据结构。

**【实现证据】** 当前 Lattigo 切片已包含六个独立包：`integer/z2n`、`integer/homchain`、`integer/evaluator`、`integer/treecompile`、`integer/treeplan` 和 `integer/treeeval`。其中 `z2n` 已在 commit `96ebe58` 跟踪；其余新包在本快照中仍为未跟踪工作树内容。

**【测量结果】** 2026-08-29 22:12 在上述工作树执行 `go test -count=1 ./...` 成功；22:16 的定向 fresh verbose 复跑完成全部 65,536 个有序 8-bit 乘法对的 short/full 加密测试。M1 修复后，epsilon 边界测试与完整 `z2n` 套件各重复 10 次通过，`integer/evaluator` 完整套件也在修正后的 plaintext oracle 上通过。这些结果建立 demo-only 算术切片的功能正确性证据，不是安全性、端到端树推理或算子性能结论。

### 4.1 LCPDTE：从比较次数到密钥切换与路径选择

**【推导分析】** LCPDTE 的可转移贡献应写成“一次比较/层 + 平方根级密钥切换和大密文物化 + 跨树自举批处理”。将 `O(p·2^{D/2})` 写成全部服务器环运算会遮蔽 `Θ(p·2^D)` 的原始 tensor-product/addition 展开，也会使后续整数算子替换的收益归因失真。

### 4.3 两篇工作的共同接口

**【推导分析】** 最小端到端组合是：

```text
triangle Encode
  → OBO 选中的 feature - encrypted threshold
  → range-safe A2B/A2Sign
  → encrypted branch bit
  → OBO path-state update / BSGS selection
  → B2A + MultShort leaf selection
  → strict Decode
```

**【推导分析】** 匹配 LCPDTE 的 32,768-query、32-bit、`N=2^16` 输入时，相邻位 complex packing 与 Gao arithmetic triangle packing 均需每特征 16 个 physical ciphertext。因此 triangle representation 的价值必须从转换/比较/批处理算子图中建立，不能从“输入密文数自动减少”推出。

### 5.2 架构中的三个硬约束

**【实现证据】** 第一，`he.CT` 只是 ciphertext/scalar union，不承载机器字宽度、表示模式、signedness、范围或 rounding margin。`integer/evaluator.Value` 因此作为旁路 typed layer，不直接扩展原基线类型。

**【推导分析】** 第二，OBO 的活跃阈值经加密路径权重选中后已成为密文。加密树后端必须支持 range-safe CT–CT compare；将 OBO 的 `D` 次比较与 CT–public 比较延迟组合，会形成不存在的混合基线。

**【推导分析】** 第三，加密 child digit 不能成为数据相关的 Galois rotation index。R0/R1 都必须使用 one-hot、MUX network、public diagonal rotations 或 LUT 完成 oblivious selection，因此“树深降低”必须与选择宽度和批填充率联合评估。

## 6. 已实现进展与当前测量

### 6.1 纯数学 `z2n` 谕机

- **【实现证据】** 支持 `n∈{8,16,32,64}`，实现 polynomial reduction、binary/triangle encoding、加乘 wraparound、逐系数 strict decode、`τ` 及其逆映射。
- **【实现证据】** 保留上游 commit `08f1eb8...` 的 128-bit fixed-point roots 溯源，计算使用 256-bit precision。
- **【测量结果】** `n=8` 覆盖全部 256 个字的编码/解码，以及 65,536 对操作数的 Add/Multiply 环穷举。`n=16/32/64` 覆盖固定边界与确定性向量，不是全空间穷举。

### 6.2 `homchain` 高精度同态变换

- **【实现证据】** 已实现 normal U/V、special-`b0`、fused-`t`、fused-`t^{-1}` 变换对，并从实际 diagonal indexes 生成 naive/BSGS rotation 和 Galois-key 集。
- **【测量结果】** 在明确标记 `FUNCTIONAL-NOT-SECURE` 的 `LogN=8` 参数上，4-word 加密 Z-To-C/C-To-Z round trip、one-hot word 无跨块串扰、fused `t/t^{-1}` round trip、special-`b0` 约定和 full-slot/block oracle 一致性全部通过。

### 6.4 树语义、R0/R1 和成本分支

- **【实现证据】** `treecompile` 支持有限 float32 数值分裂、单输出加性 forest、完整树 padding、MSB-first 叶子索引和显式 base-score/output-space 语义；对 categorical、`default_left`、非有限数值与多输出模型 fail closed。
- **【测量结果】** 提交的 depth-8/10/12 XGBoost fixtures 按 raw margin 语义编译，fixture rows 与预测二进制工件通过 regression/R0 测试。
- **【实现证据】** `treeplan.CompileR0` 将 `g∈{1,2,3,4}` 个连续二叉层组成 `2^g` radix supernode，保留原分裂和叶子；R1 则以显式有序阈值表示多叉 interval tree。
- **【实现证据】** `treeeval` 保留 conservative-uniform OBO 对照：对 `L=2^D` 个叶子，它使用 `D` 次 CT–CT compare；full-level 使用 `L-1` 次 CT–public compare。Stage-2 `treeplan` 另行实现 source-faithful OBO control：根节点一次 CT–plaintext compare，深度 `1..D-1` 共 `D-1` 次 selected CT–CT compare，且根节点不收取不存在的 width-one blind selector。
- **【实现证据】** 通用 evaluator 使用 `PublicScalar` 保留 real、unsigned 与 two's-complement signed 常量的精确位模式和 bit width；每次比较必须携带 `ComparisonPolicy`，显式绑定 signedness、operand ranges、comparator variant 与 overflow contract。
- **【实现证据】** `treeplan.CompileR0` 颁发包内私有的 source/plan SHA-256 证书。`Validate` 检测计划突变，`VerifyAgainst(source)` 同时检查 source binding 并重新编译比对；手工构造、JSON round-trip、篡改计划和错误 source 都不能自标为 R0 equivalent。
- **【实现证据】** typed schedule planner 将 source-faithful OBO control 与 conservative CT–CT、eager-active CT–CT、eager-all CT–plaintext、state-aware fused LUT 四类日程分开。日程证书分别绑定 source、radix plan、request、logical/proof structure 与包含物理观测的 full plan；逻辑字段、proof reference 或 physical observation 被篡改时验证失败。fused proof 当前统一为 `external_unverified` 并禁止进入 benchmark。
- **【实现证据】** physical profile 将 packing、comparator streams、LUT I/O、乘法/加法、A2B/B2A、rotation、relinearization、rescale、key switch、transform、refresh/bootstrap、峰值密文/字节与 wall time 类型化；`not_measured` 与 measured zero 分离。predicate/LUT dependency rounds 仅为逻辑下界，end-to-end HE depth 与 bootstrap 数保持未知。
- **【实现证据】** `CompileOrderedForest` 为有限 float32 split 建立独立的 unsigned comparator view：负值反码、非负值翻转 sign bit，`-0/+0` 统一为同一 key，NaN/±Inf fail closed；编译结果深拷贝 source forest，不改变树形、leaf bits 或预测语义。
- **【测量结果】** 定向测试覆盖 `uint64(2^63+1)`、`int64(-2^62)`、相同 `0xff` 位模式的 unsigned/signed 分歧、声明范围越界、signed subtraction no-overflow 的范围证明，以及 tree type 与 comparison policy 不匹配。负 `NumOutputGroup`、单阈值 NaN/Inf、非有限 leaf/base margin 均 fail closed。这些是通用/plaintext backend 契约测试，不是已完成的加密 comparator 证据。
- **【测量结果】** ordered-float32 view 在边界值、subnormal、signed zero 与 100,000 组固定种子随机有限 float32 对上保持 `<`、`>=` 和相等关系；fixture route 与 leaf bit 一致，`treecompile` package、`go vet` 和 formatting 检查通过。这是 R0 comparator 输入视图证据，不是 encrypted comparator 证据。

**【复现事实】** [Gao sine kernel 契约](../phase3_design/gao_sine_kernel_contract.md) 将非线性内核进一步固定为 $x=u/16\in[-1,1]$ 上的 33 项升序 Chebyshev 档案、一次且仅一次的 `c0/2` 约定转换，以及三轮 $p\leftarrow2p^2+r_j$。理想目标是 $\sin(32\pi x)/(2\pi)=\sin(2\pi u)/(2\pi)$；真实内核仍是固定多项式近似，因而“exact”只修饰 dyadic 常数和递推，不修饰 sine 求值。

**【实现证据】** `integer/homchain/sine_kernel.go` 已用 `big.Int/2^128` 与 256-bit 精度实现常数档案、独立 Clenshaw 明文 oracle 和 isolated ciphertext evaluator。第二轮 operational-dispatch 修复将多项式包装为覆盖全部 16 slots 的 `PolynomialVector`，将三枚 recurrence constants 包装为 16-element `[]*big.Float`，从而强制 Lattigo 走绑定 encoder 的 vector operand 分支；透明密文 sentinel 能区分会损失 `2.66736330×10^{-17}` 的 scalar branch 与 256-bit 精确 round trip 的 vector branch。密文路径随后显式执行三轮 `MulRelinNew → Rescale → Add(y,y) → Add(r_i)`；输入证书、operand trace、exact scale、重线性化 key、逐阶段状态和不可变性均 fail closed。它不调用 `mod1.SinContinuous`，也不以 `DropLevel` 或 scale retag 伪造日程。

### 6.9 Boolean 转换的 plaintext conformance 层

**【实现证据】** `integer/z2n/boolean_oracle.go` 固定了 Gao 转换层的精确 plaintext 边界：paired `LUT_ID/LUT_MSB` 值、LSB-first low/high Boolean halves、standalone B2A residue重组，以及 direct B-A2B 的 `d=n/w`、full-packing、偶数 `d`、exact-batch 和 `[A.low,A.high,B.low,B.high,…]` 输出顺序。API 注释与类型明确声明这些函数不执行 CKKS encoding、LUT approximation、bootstrapping 或 homomorphic conversion。

**【测量结果】** 五轮定向 gate 与当前工作树复跑覆盖全部 256 个 residues，raw `ArithmeticEncode` coefficient/residue、输入不变性、key/state profile 全部通过；normal-U、canonicalized-representative 与 swapped-half controls 能区分目标路径。首审 0/2/0 后的独立稳定复审为 0/0/0。验收阈值为 slot/coefficient/bit error `<5×10^{-4}` / `<5×10^{-4}` / `<10^{-3}` 且 rounding margin `≥0.499`；不同随机密钥/噪声运行的精确误差快照有波动，因此不将某次较小数值写成稳定上界。该切片仍是 `FUNCTIONAL-NOT-SECURE` Gao-to-Lattigo adaptation；raw upstream intermediate trace、secure profile 和 benchmark 均未完成。

**【实现证据】** 同参数链适配器 `NewB2AFullAtLevelCircuit` 现可在固定 A2B LogN=5/Q=`[50,35×20]`/P50/S35 参数下，于指定 level 编译 fused-`t^{-1}` U pair。`L5` ingress 使用精确 `q_5` matrix scale，profile 绑定四个 words、16 slots、rotations `[1,2,12,14]`、Galois elements `[5,17,25,41]`、source/compiled-plan digests 与 profile digest `01d138a6…168588a3`，输出为 `L4` 且保持 exact default scale。kernel profile v3 通过同一次 shared `EvaluateMultiPoly` 的 target-scale correction 将 Boolean outputs 固定为 exact `L5,S35`，没有增加 level、named operation 或 `SetScale`，并以 digest `44471389…3986519e` 封存。两次 kernel 调用从合成 normalized low/high prefix codes 生成真实 MSB ciphertexts，并由同一 secret/keyset 下的 B2A 在 `[00,10,A5,FF]` 上重构 residue。五轮定向测试、legacy B2A regression、post-bind key-identity fail-closed、vet 与 gofmt 绿色；kernel-v3 与 repaired B2A producer–consumer seam 的稳定独立复审为 0C/0M/0m。该接受仍只覆盖合成 prefix inputs 和四个代表词。

### 7.2 Radix / integer-node 的必要 break-even 条件

**【推导分析】** 对固定叶数 $L$ 的完整均匀 radix-$r$ interval tree，活跃路径的独立阈值比较数为

$$
C_r(L)=(r-1)\log_r L=\ln(L)\frac{r-1}{\ln r}.
$$

因 $\ln r>1-1/r$，$(r-1)/\ln r$ 在 $r>1$ 上严格递增，所以 binary 在这类独立比较构造中最省比较。若 $r=2^g$、$L=2^D$，则比较数为 $(2^g-1)D/g>D$，而依赖轮数降为 $\lceil D/g\rceil$。因此“树更浅”本身不是 HE 加速证据。

**【创新假设】** 可检验的 R1 优化只保留三条机制：一次 A2A/A2B 表示转换服务同一 feature 的多个阈值；把 $r-1$ 个阈值差打包进 exact-batch B-A2B；把嵌套谓词的 unary code 直接融合为 arithmetic digit/LUT。必要的测量条件是

$$
\frac{T_{\mathrm{batch}}(2^g-1)+T_{\mathrm{digit}}(2^g)+T_{\mathrm{refresh}}}{g}
<T_{\mathrm{cmp}}(1)+T_{\mathrm{select}}(2)+T_{\mathrm{refresh}},
$$

且两侧必须采用相同预测语义、安全/正确性 profile、全部 ciphertext blocks 与 physical calls。

**【推导分析】** R0 的 exact-fusion 机会更窄：只有 reachable splits 全部作用于同一 feature 的局部子树，才可在固定整数域上排序 cut points，并以 exhaustive interval-to-leaf/state certificate 编译成等价 LUT/interval node。mixed-feature 子树的域通常是笛卡尔积，不能沿用该成本。完整预注册、实验 arms 与 falsification criteria 见 [radix/integer-node 假设稿](../phase3_design/radix_integer_tree_hypotheses.md)。

## 9. 当前结论

1. **【复现事实】** LCPDTE 已经被重建为一条可核验的因果链：OBO 减少比较次数，GenOH/BSGS 减少密钥切换和大中间态物化，level-major 批调度减少跨树自举调用。该链不消除按节点展开的 tensor-product/addition 工作。
2. **【复现事实】** Gao–Zheng 已经被重建为表示—映射—模式转换三层系统。其摊销常数自举主张依赖满批；上游 comparison 需增加溢出安全语义才能用于通用私有树阈值比较。
3. **【实现证据】** Lattigo 移植已通过高精度数学谕机、full-slot 变换、typed codec、demo-only short/full multiplication、独立接受的 standalone B2A、A2A-I、isolated sine/3DA、完整固定 A2A-e、exp46 前置件、all-256 首轮 refresh→kernel、四词 kernel→同链 B2A 接口与固定 full-serial A2B 切片，以及 XGBoost 语义编译、generic tree evaluator 和 typed R0 日程规划器建立可执行基础。full-serial A2B 的稳定修复复审为 0C/0M/0m；接受范围保持 fixed small functional-not-secure。
4. **【实现证据】+【测量结果】+【独立审计】+【创新假设】** direct rank-one sign fusion、fixed signed-int8 Phase-B comparator、public-leaf T0、periodic selector、producer-bound prefix、fixed-L6 ingress/comparator、child decoder 与 repaired float64 terminal 均在各自 bounded `FUNCTIONAL-NOT-SECURE` profile 下通过独立审计。C72 闭合 public root；C73 以 all-node packing 让 170 个 depth-2 查询的三个内部节点共用一次 A2B；C74 以一个 typed orchestrator 闭合 root CT–PT、below-root selected-threshold CT–CT 与 real-leaf terminal 的完整小参数路径；C75 又在 N16/L11 Route B 上执行同序 selected-child 路径，512 个查询、2,048 个输出槽零失配。C76-R4 先完成 7 对 fixed-AB 发现系列，再完成 16 对交替顺序确认；确认系列 32 个测量进程均零失配，并稳定实现已注册的 path-terminal CT–CT 操作删除。terminal 中位耗时下降 86.85%，complete-circuit/lifecycle 臂中位数下降 3.94% / 1.25%，注册方向判据通过但 ≥10% 性能晋级门失败；配对 IQR 大于配对中位差。该创新定位为“预测等价、方向确认的 terminal 结构消融”，不是稳定端到端加速或一般 radix 优越性。
5. **【测量结果】+【实现证据】+【独立审计】+【推导分析】** exact LogN=16 sensitivity、adapter、capacity/profile、C55–C65、canonical transport/configuration identity、combined observed ModUp/Trace implementation、完整 RBDFT type-01–07 wire/payload streaming、live-capacity v4 design 与 payload-free `AuthorizeBuild` 均在各自范围内独立接受。C61 只接受 pure-wire codec，C63 只接受 owner-linearized install design，C64 只接受 vendor structural assembly support，C65 只接受 fresh-capacity first-build authorization。C67 的 fail-close 记录触发 phase-relative repair；C68/C69 完成 ModUp/Trace/C2S 作者门，C70 冻结首轮低半字节 A2B，C71 完成完整 byte domain 的两轮 8-bit A2B。C76 又将 C75 的 41-key/124-sample 精确 exposure inventory 与 main/ephemeral estimator rows 绑定为作者侧 application-security `CONDITIONAL-PASS`。该结论尚待独立安全审计，不是无条件 128-bit protocol proof；parameter maturity 保持 `parameter_candidate_unverified`，Route A full-packed construction 仍开放。
